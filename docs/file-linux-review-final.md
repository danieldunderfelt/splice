1. **P1 — A disappearing recipient still redirects the drop.** [helper.rs:244](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-files/src/helper.rs:244), `Shelf::set_peers`. Select B, then receive `[A]`. Rebuilding selects A; GTK ignores `set_selected(INVALID_LIST_POSITION)` while autoselection is enabled. `SourceDrop` consequently names A despite the warning. Keep the explicitly chosen peer ID separately and invalidate it until the user chooses again. [GTK selection implementation](https://raw.githubusercontent.com/GNOME/gtk/main/gtk/gtksingleselection.c).

2. **P1 — Clipboard invalidation still happens too late, or never.** [datacontrol.rs:365](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-platform/src/linux/datacontrol.rs:365), `selection`, and [clipboard.rs:214](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-platform/src/linux/clipboard.rs:214). Both backends emit changes after reading inline text. Data-control emits nothing for an empty selection. During that interval, the previous file offer remains acceptable and a completed Receive can overwrite the newer clipboard. Assign and submit the shared generation before reading, including empty changes. Carry freshness into queued native publication; the app-side check alone cannot reject a stale `SetOffer`.

3. **P1 — Save does not retain its receipt.** [mod.rs:859](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/mod.rs:859), `save_receipt`. Rust captures only `info.paths` in these closures; `info.lease` drops when the function returns. Start a large Save, then Clear: core can delete the source while copying is underway. Explicitly move the lease into the blocking operation and drop it after copying finishes. A standalone Rust ownership probe confirmed this capture behavior.

4. **P1 — An obsolete attach can erase retained history.** [mod.rs:323](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/mod.rs:323), `attach`, and [content.rs:104](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/content.rs:104), `Content::attach`. Hold the first attach at its portal probe, detach/reconnect, then release it. The old job can install the dead `FileHandle`; failed retention requests then remove journal records and receipts. Tag attach work with an engine incarnation and reject obsolete work before mutation. A stopped engine is not evidence that receipt data disappeared.

5. **P2 — Failed Clear permanently removes the recovery entry.** [mod.rs:884](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/mod.rs:884), `clear_receipt`. The bridge deletes its journal record, views and receipt before requesting core cleanup. Core can reject cleanup because two other clears are running, another consumer holds a pin, or filesystem cleanup fails. The files remain but disappear from the shelf and its restart journal. Preserve recoverable metadata until cleanup succeeds; restore retention and report the error on failure.

6. **P2 — Closing the shelf invalidates completed receipt drags.** [mod.rs:423](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/mod.rs:423), `disconnected`, and [content.rs:206](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/content.rs:206), `register_receipt_view`. Drag a retained receipt into an application, then close the shelf. Every receipt view is retired, including dropped/read views and open readers. These new view IDs are also never journaled, so saved URLs fail after restart. Give completed receipt views durable ownership until explicit Clear, retaining the published IDs.

7. **P2 — Read-only root directories cannot be saved.** [copy.rs:60](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/copy.rs:60), `copy_root`/`copy_entry`. Save a receipt whose root directory is `0555`. Metadata is applied before moving it from staging into its destination parent. Linux requires write permission on a directory when changing its parent, so publication fails with `EACCES`. Keep the staged root writable through rename, then apply its final metadata through a retained descriptor. The existing test makes only a nested directory read-only. [Linux rename permission check](https://raw.githubusercontent.com/torvalds/linux/master/fs/namei.c).

8. **P2 — Staging temporarily exposes private file contents.** [copy.rs:31](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/copy.rs:31), `copy_receipt`/`copy_entry`. With umask `022`, saving a `0600` regular file into a shared directory creates a `0755` staging directory and a `0644` output file. Other users can read the contents during copying and `sync_all`, before final permissions are applied. Create the staging directory atomically with mode `0700` and staged files with `0600`.

9. **P2 — Retry is unreachable and tracks the wrong transfer.** [mod.rs:947](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/mod.rs:947), `retry_receive`/`sync_files`. Failed and cancelled transfers map to `OfferStateDesc::Available`, so the helper never displays its Retry branch. Even if invoked, Retry tracks the old transfer ID and discards `FileReply::Receiving(new_id)`. The successful retry therefore never becomes a retained receipt. Emit the retryable state and track the ID returned by core.

10. **P2 — Automatic preparation strands rows beyond the eight-view limit.** [helper.rs:917](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-files/src/helper.rs:917), snapshot handling and `drag_source`. Open a shelf containing nine receipts. It prepares every row, but the service admits only eight. Dragging the rejected row merely reports “not ready”; it does not request preparation. Eight incoming offers can likewise occupy every slot ahead of receipt rows. Prepare on user demand and release unused preparations so every row remains actionable.

11. **P2 — Outbound backpressure still drops drag lifecycle events.** [helper.rs:755](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-files/src/helper.rs:755), `send`. Once its 256-message queue fills, `DropPerformed`, `DragCancelled` and `DragFinished` are discarded with only a log warning. A dropped preparation request also remains marked pending indefinitely. Reserve reliable bounded delivery for lifecycle messages, or close the connection on overflow to trigger cleanup; propagate admission failure back to pending state.

12. **P2 — Hello can arrive before Connected.** [shelf.rs:124](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/shelf.rs:124), `serve_client`. The reader thread starts before `Inbound::Connected` is enqueued. The production helper sends Hello immediately, so the reader can enqueue it first. `Runner::message` ignores the unknown client; the subsequent Connected leaves it permanently unready. Enqueue Connected before allowing the reader to deliver messages.

13. **P2 — Superseded publications leak portal transfers.** [clipboard.rs:326](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/clipboard.rs:326), `publish`, and [fileportal.rs:50](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-platform/src/linux/fileportal.rs:50), `PortalExport`. Change the clipboard while export is running. The second freshness check returns through `?`, dropping an export created with `autostop=false` without calling `StopTransfer`. Native publication errors have the same consequence. Add cancellation-safe ownership beginning immediately after StartTransfer, with cleanup on every unsuccessful exit.

14. **P2 — Zero-length IPC records still leak attached descriptors.** [ipc.rs:398](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-files/src/ipc.rs:398), `recv_record`. A zero-length SEQPACKET record carrying `SCM_RIGHTS` returns `None` before received descriptors are wrapped. Connection teardown does not close those installed descriptors. Parse and own ancillary descriptors before the zero-length branch, as already done for truncation.

15. **P2 — Supported timestamps are changed.** [mount.rs:396](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-files/src/mount.rs:396) and [copy.rs:163](/Users/daniel/Work/splice-file-work/linux-final/crates/splice-app/src/file_service/copy.rs:163), `system_time`. For `{seconds: -1, nanos: 500_000_000}`, the correct timestamp is −0.5 seconds. FUSE returns epoch zero; Save returns −1.5 seconds. FUSE also discards nanos when seconds equals zero. Use signed seconds plus the positive fractional component. A pure probe using both committed functions confirmed these results.
