# Parent review of Linux receipt handling at c8b6e64

These are code-inspection findings for the next Linux repair. No interactive tests were run. The independent Astra review is in progress.

1. `Runner::clear_receipt` removes the native journal and receipt before awaiting core `ClearReceived`. A denied Clear, stopped engine or bounded core queue failure loses the row and all native restore ownership while core still retains the data. Keep a durable clearing state or preserve metadata until core completion; release consumer pins for the request, restore the row and lease on failure, and only report success after acknowledgment. Newly arriving reads must not race the busy-reader check.
2. `Content::attach` interprets every `retain_received` error as permanently missing data and removes the journal. Queue pressure is a transient error, and recovery can leave an intact receipt temporarily unavailable. Do not discard durable metadata on an arbitrary error. Reconcile against actual core state, expose unavailable retained records, and retry safely.
3. The extra received-row `SaveReceipt` duplicates core staging with a separate `copy.rs`. It uses an ordinary created staging directory before permission restriction, unbound path-based cleanup, blocking source open if a FIFO replaces a regular file, stale metadata before opening, and incorrect pre-epoch fractional timestamps. Its closure only captures `info.paths`, so the claimed retained lease may be dropped through disjoint closure capture before copying. Parent has removed this optional duplicate operation and its protocol/hooks/module in the root checkout. Preserve that removal when integrating follow-up commits. Keep incoming-offer Save to folder through core, and received-row Copy to clipboard, Reveal and native drag for local copying. No replacement copy engine is needed for the approved workflow.
4. `sync_receipts` currently calls `Content::receipts`, cloning every full manifest and receive lease on each 200 ms tick before comparing serialized summaries. Build display summaries without cloning complete trees or scanning them at every progress tick; update only when retained receipt metadata changes. This is particularly relevant at the legal 128 receipts by 256 KiB manifest limit while input is active.

Existing known fixes assigned to Kimi are separate: disable operations when no durable storage exists; bound helper snapshots and fetch selected paths on demand; register completed receives even when clipboard publication is superseded.

5. Kimi's `30b7acb` orphan discovery skips a Ready transfer when its offer is absent. After restart, the core normally has no original offer records. Parent added `ReceivedLease::manifest() -> &Manifest` in root core specifically for this. Recover each Ready receive by its own lease and metadata, using the transfer peer for the origin label. Do not require an offer record. The public API is available after copying the latest root core snapshot for compilation; exclude that snapshot from the Linux-owned commit.

6. Final shelf copy should use human-readable file sizes and avoid printing raw Unix expiry timestamps. Filename newlines should remain valid paths but must not turn a summary label into dozens of rows. Apply presentation-only formatting after the lifecycle integration; no GUI test is needed in this session.
