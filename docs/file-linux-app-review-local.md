# Linux integration findings before final review

This is a working review record. No interactive testing was performed.

1. `file_service/clipboard.rs::publish` awaits portal export after `mod.rs::Done::Received` checks the clipboard epoch and per-client intent. A local copy or a second Receive during export can be overwritten by the old completion. Serialize publication and receive intent allocation, recheck the generation immediately at publication, retain a global latest intent across clients, and make the native backend reject a stale queued publication where possible. The epoch is currently only advanced after slow inline clipboard reads in native backends; inspect that ordering too. Cover this with a deliberately blocked mock publisher/exporter.
2. `file_service/mod.rs::enforce_committed_limit` and `journal.rs::insert` evict completed FUSE views by age/order. The approved plan explicitly retains completed views until the user clears them. Reject new admission at capacity, expose explicit Clear with a saved-URL warning, and keep active reads/current clipboard pinned. Journal writes must be durable and bounded, preserve the old state on write failure, and report corrupt journals instead of silently replacing them with an empty history.
3. Linux offers marked Ready still call `PrepareDrag` for the original remote offer. A received file should drag, reveal, save, or republish from its retained local receipt after disconnect/revocation/restart. Orphan receipts currently disappear from the shelf. Add a receipt representation and local native drag paths with explicit retained pins, without re-transferring. Keep source offers and individual transfer actions distinguishable. Add Cancel/Retry/Clear controls; the current helper exposes only Receive/Save/Dismiss.
4. `Runner::message` rejects every message when `jobs.len() >= MAX_JOBS`, including drag drop/cancel/finish control. Admission limits must reject new work without dropping cleanup/authorization events. `Bridge::{attach,detach,open_shelf}` also silently drops full-queue events; lifecycle needs reliable bounded delivery/coalescing.
5. `MAX_LIVE_VIEWS` counts all non-Restored views, including completed live-session views. It can stop all new drags after 32 successes, independent of the documented receipt quota. Separate active preparations from retained completed views, count pending preparations in admission, and expire dropped-but-unread views after the declared 24 hours.
6. `Content::persist` logs errors and still serves content. This violates the restart path guarantee if the view journal fails. Do not publish a successful path until its durable ownership record is written. Restore validates every bounded manifest/ID and never exposes an invalid path from a corrupt journal.
7. `run` falls back to a global temp journal on config-dir failure. Remove that fallback. Surface the concrete startup error while preserving input operation.
8. New native file clipboard capture should invalidate the prior unaccepted file offer immediately, before asynchronous clipboard reads. Current `tap` increments only a local epoch then waits for capture; the old offer can still be accepted during that wait. Preserve safe non-file URI text, and never broadcast pathname text or portal keys.

The native helper also rebuilds all rows on every progress update. Check source drag/controller lifetime and selection stability under progress updates. The independent native review covers GTK/FUSE details.
